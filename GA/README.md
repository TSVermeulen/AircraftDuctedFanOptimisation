# Genetic Algorithm modules of the Unified Ducted fan Code (UDC)

This folder contains the relevant modules for the Genetic Algorithm (GA) implementation of the UDC. These modules and their interconnections are visualised in the diagram below. To execute an optimisation, the configuration needs to be set in config.py. This file defines the operating conditions, initial reference geometry, constraints, objectives, and setup of the algorithm itself (population size, termination controls, etc.). Three different options are provided to execute the genetic algorithm optimisation, being:

- main.py: A U-NSGA-III implementation using serialised evaluation.
- main-parallelised.py: A basic μ+λ GA implementation using parallelised evaluation.
- main-parallelised-UNSGAIII.py: A U-NSGA-III implementation using parallelised evaluation.

## Core Utility Module Descriptions

- *config.py*: Contains the problem definition (reference geometry, initial population generation, population size, termination conditions sliding window, objectives, and constraints, operating conditions).
- *termination_conditions.py*: Defines the single-point and multi-point termination conditions. Considers changes in objective space, the maximum generation count, changes in design space, and constraint violations as termination criteria.
- *utils.py*: Contains three general utility functions. Used to ensure the correct paths are visible to the python interpreter when executing, calculating the correct number of reference points needed for U-NSGA-III, and to correctly format the figures generated by the PostProcessing class in post.py.

## Population/Individual Interface Module Descriptions

- *init_designvector.py*: Contains the class responsible for creating the design vector corresponding to the configuration in config.py.
- *init_population.py*: Module responsible for the creation of the initial population used to start the optimisations. Generates an initial population based on perturbations applied to a known reference design vector.
- *design_vector_interface.py*: Module responsible for manipulating the Pymoo design vector dictionary into the data dictionaries required by the UDC, and for reconstructing the design vector dictionary using provided UDC data dictionaries.

## Genetic Algorithm Module Descriptions

- *problem_definition.py*: Main class implementing the Pymoo single-point problem definition.
- *multi_point_problem_definition.py*: Implementation of a multi-point pymoo problem definition.
- *repair.py*: Implementation of a repair operator which corrects unphysical design vectors back to the physical design space.
- *constraints.py*: Implementation of single- and multi-point constraints.
- *objectives.py*: Implementation of different objectives. New objectives should be added here so that they can be selected within config.py.
- *checkpoint.py*: Module to write intermediary optimisation results to temporary '.dill' files. Useful in case evaluations/computers crash to recover partially completed optimisations.

## Postprocessing Module Description

- *post.py*: Implementation of the PostProcessing class. Enables visualisation of the optimised design(s), Pareto front, and convergence behaviour of an optimisation based on the loaded 'results.dill' file obtained from a (partially) completed optimisation. Also enables comparisons between multiple result objects.
